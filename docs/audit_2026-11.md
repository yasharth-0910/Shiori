# Audit of the shipped code, November 2026

Run 2026-11-26 on commit 6262dbf, extractor version 0.3.0. Scope: `core/`, `sidecar/`, `app/electron/`, `app/src/`, `packaging/` (10,951 lines). No source file was changed. Machine: MacBook Air M4, 24 GB, on AC power.

## Summary

- No shipped code imports `eval/`, `collector/` or `training/`.
- Model calls dominate. On the three timed documents they are 99.6% to 99.9% of the time to fields. In the staged run, parse, segmentation, rules and checks together are under 0.4 s per document. In packaged mode, ingest took at most 0.8 s.
- The code has little dead weight: about 10 dead lines and 12 duplicated lines. About 600 more lines are dev-only code that lives in shipped folders.
- The installer can lose about 70 MB of 467 MB installed (roughly 22 MB of the 193 MB `.dmg`, estimated) with packaging changes only.
- Two items are not cleanups but should be fixed: F4 (window can stay hidden) and F5 (FastAPI telemetry is not switched off in code). Both are fixed in commit 719300e (D-117).
- A baseline of 75 outputs is recorded and replays identically.

### F1. Electron locales

- Where: `app/electron-builder.config.cjs:36-58` (no `electronLanguages` setting).
- Evidence: 220 `.lproj` folders in Electron Framework, 50.4 MB. Keeping `en`, `en_GB`, `ja` (2.0 MB) frees 48.4 MB, 12.3 MB compressed.
- Risk: low. Native dialogs would show English or Japanese only. Not built or tried.

### F2. Unused llama.cpp files

- Where: `app/electron-builder.config.cjs:44` copies the whole release folder.
- Evidence: following `otool -L` from `llama-server` needs 11 libraries and binaries. The other 31 files are 11.4 MB (4.4 MB compressed), including `llama-connect` (8.2 MB) and `ggml-rpc-server`. A folder holding only the needed files loaded Qwen3.5-9B and gave the same answer as the full folder to one fixed request.
- Risk: low on macOS arm64. Only one request was compared. Windows and Linux were not checked and may load backend libraries at run time, so filter executables only there, or work out each platform's list separately.

### F3. Sidecar excludes

- Where: `packaging/sidecar.spec:28`.
- Evidence: PyInstaller's xref shows PIL and fontTools pulled in only by `pymupdf`, yaml by optional paths in uvicorn, starlette and numpy. A trial build excluding `PIL`, `yaml`, `setuptools`, `fontTools` is 88.5 MB against 99.0 MB (40.9 against 46.0 MB compressed). Rules-only output over all 60 dev documents was identical to the installed sidecar: 57 done, 3 refused as scans.
- Do not also exclude `ssl`: that build crashed on start (`uvicorn/config.py` imports it).
- Risk: low. The model path was not run on the trial build.

### F4. Hidden window in a packaged app

- Where: `app/electron/main.ts:127`, `show: !process.env.SHIORI_SHOT && !HLCHECK`.
- Evidence: reading the code. The screenshot and highlight switches elsewhere in the file are gated on `app.isPackaged` (lines 43 to 58, 121, 143 to 156). The `SHIORI_SHOT` read on line 127 is not, so a packaged app with that variable set opens no visible window. `tests/test_app_llama.py` does not cover this line. Not reproduced in a running app.
- Risk of fixing: none (use the gated `shot` value).
- Fixed in commit 719300e (D-117): the window is hidden only through the gated `shot` value. Test in `tests/test_app_no_network.py`.

### F5. FastAPI telemetry

- Where: `sidecar/server.py:657`, `FastAPI(...)` with no `telemetry` argument.
- Evidence: FastAPI 0.165.0 turns on OTLP export when `FASTAPI_OTEL_AUTO_CONFIGURE=true` and an endpoint variable is set. The app passes its environment to the sidecar (`app/electron/sidecar.ts:33`). I started the installed sidecar with both variables pointing at a loopback port: it logged "automatic telemetry configuration failed" (the export packages are not bundled) and ran normally. So nothing can be sent today. If those packages ever arrive as a dependency, the same variables would export traces, and FastAPI's default includes exception messages, which could hold document text.
- Fix: pass `telemetry={"auto_configure": False}` (and consider turning tracing, metrics and logs off). Add a test.
- Risk: none for output.
- Fixed in commit 719300e (D-117): `create_app` turns telemetry off in code, and the app starts the sidecar without `OTEL_*` and `FASTAPI_OTEL_AUTO_CONFIGURE`. Tests in `tests/test_app_no_network.py` and `app/test/models.test.ts`.

### F6. Dev check hooks in the app

- Where: `app/electron/main.ts:43-47`, `:120-121`, `:140-236` (screenshot and cancel drivers); all 208 lines of `app/electron/hlcheck.ts`; `app/src/App.tsx:24-29` (loads `fixture.json`, which the installer excludes).
- Evidence: gated off when packaged (except F4) but compiled into `app.asar` (`hlcheck.js` 14 KB).
- Related: `sidecar/__main__.py:85` reads the dev switch `SHIORI_NO_SCALARS` in the packaged app too, so that variable changes output there. Gating or removing it is a one-line change.
- Users of these: `scripts/highlight_check.py`, `tests/test_app_llama.py` (asserts the source strings).
- Risk: low for users. Medium effort: the dev checks need a new home.

### F9. Duplicated helpers

- `_union`: identical, `core/shiori_core/segment.py:298` and `extract_text.py:173` (7 lines).
- `_strip`: identical, `checks.py:57` and `extract/rules.py:780` (2 lines).
- `_is_pua`: same test twice, `normalize.py:42` and `pdf/__init__.py:70` (2 lines).
- `MONTHS` short names: `app/src/deadlines.ts:4` and `summary.ts:17`.
- Do not merge `checks.value_in_citation` with `rules.value_in_citation`: the checks version also accepts ellipses and original text. Merging changes output.

### F10. Rules run twice

- Where: `sidecar/__main__.py:86` calls `rules.extract` again to learn which fields were found.
- Evidence: two calls per document in the timing run, 0.3 to 4.2 ms each.
- Worth doing only as tidying. No speed gain a user could notice.

### F11. Runtime dependencies

- Where: `pyproject.toml` `[project].dependencies`.
- Evidence: `lxml`, `networkx`, `onnxruntime`, `opencv-python-headless`, `pillow`, `pyyaml`, `tqdm` are imported by no shipped file. They serve the NDLOCR-Lite checkout, and the installed app refuses scans. In `.venv`: onnxruntime 66 MB, cv2 123 MB, lxml 21 MB, networkx 13 MB. Moving them to a dependency group saves nothing in the installer (F3 covers PIL and yaml there).
- `numpy` is imported at the top of `pdf/__init__.py:18` and `ocr/__init__.py`, so it ships (7.2 MB) although only OCR uses it. Removing it needs lazy imports plus a spec exclude. Not tried.
- `app/package.json`: every dependency is used. `openpyxl`, `bs4`, `httpx` are dev groups and used.
- Risk: low. CI and `uv sync` instructions would need the new group.

### F12. Tests

- 984 functions in `tests/`: no identical and no near-identical (similarity 0.85 or more, 6+ lines) bodies.
- A fake llama HTTP server is written out five times: `tests/test_llm_extract.py:518, 585, 647`, `tests/test_sidecar.py:906`, `tests/test_translate.py:23`. A shared helper saves about 50 lines.
- `tests/test_app_llama.py`: the first two tests check the same gating pattern. Its "no key in argv" check overlaps `app/test/models.test.ts:176`.

## Observations that are not cleanups

These change behaviour or output, so they need your decision.

- **Scalar fallback cost.** `extract_scalars` took 245 s of 1,907 s of model time (13%) on the 15 labeled dev documents and added no field: 58 fields asked, 3 non-null answers, none kept. D-95 already measured very little gain. This is 15 dev documents only; removing it (about 180 lines, `extract/llm.py:668-849`) could change results elsewhere. Risk: medium.
- **Startup order.** `app/electron/main.ts:87` and `:94` start llama-server and then the sidecar. Starting them together would hide the shorter wait.
- **Translation** adds 28 to 330 s after the fields are ready.

## Checked and left alone

- Import boundary: grep over `core/`, `sidecar/`, `packaging/` for `eval`, `collector`, `training`, cloud SDKs, `requests`, `httpx`: none. Same for `app/src`, `app/electron`, `app/test` paths. `tests/test_import_boundaries.py` covers `core/` and `sidecar/`. The installer's `app.asar` (186 files) holds no `node_modules`, `fixture.json` or `doc.pdf`.
- `OcrEngine` protocol (one real engine plus a test fake, D-36) and the single PDF module (D-28): deliberate.
- `ISSUERS` and `APPLIES` copies in TypeScript: guarded by tests.

## Baseline

Folder: `data/cache/audit_baseline/` (gitignored, holds document text, local only).

Compare after any cleanup (about 20 s, no model, no network):

```
.venv/bin/python data/cache/audit_baseline/baseline.py compare
```

Exit code 0 and "75 of 75 outputs identical, 0 model requests not in the cache" means nothing changed in what it covers.

- `full/`: the 15 documents in `data/eval/dev/labels` (12 HTML, 3 PDF) through the sidecar's worker: pages, sentences, document type, fields, live events, model request hashes, translation prompts (model stubbed). 56 model answers recorded with Qwen3.5-9B and llama.cpp b12651.
- `rules/`: all 60 dev documents in `data/eval/label_set.json`, rules only, 8,616 sentences. 3 of them use OCR, so compare needs `models/ndlocr-lite`.
- `replay/`: the recorded answers. A changed prompt or schema is a cache miss and fails the compare.
- `SHA256SUMS`: 90 files (15 full, 60 rules, 15 replay). `meta.json`: model hash and server build.
- Checked: compare passed twice after recording. With `llm.WINDOW` changed from 3 to 2 it failed (60 of 75 identical, 90 misses).
- To record again on purpose: delete `SHA256SUMS` and `replay/`, then run `record` (about 32 minutes).

Not covered: the HTTP layer and the translation queue (use `pytest`), real translation output, llama-server flags, the Electron app, and the PUA glyph recovery path (`pdf/__init__.py:83`, never executed here). The folder is not backed up by git, and it sits under `data/cache/`, so do not clear that folder during cleanup.

## Verification run

- `pytest -m "not corpus"` (config passed on the command line): 1,006 passed, 21 deselected.
- `node --test` in `app/`: 129 passed. `tsc` for both configs: clean. `ruff check core sidecar packaging`: clean.
- Line coverage of `core/` and `sidecar/` (stdlib `sys.monitoring`, executable statements counted from the syntax tree): baseline replay 82% (2,572 of 3,131), tests 96% (2,999). Run by neither: `debug_render.find_pdf` and `main`, `rules._date_only`, `extract_text._is_single`, `pdf._union` and `_recover_pua`, and `watch_stdin` and `stop` in `sidecar/__main__.py` (run by subprocess tests that the tracer does not follow).
