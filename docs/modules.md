### collector
- **Status:** working (Phase 1). Three adapters: `digital` (Digital Agency, `open`), `p-portal` (調達ポータル notices as HTML, `open`, D-18, D-25) and `listing` (local-government CMS sites, configured per site in `sources/sites.py`: Funabashi, Wakayama, Asahikawa, Hachioji (layout group A), Okayama, Koriyama, Nara, Niigata (group B) and Hokkaido).
- **Purpose:** download public Japanese tender documents and record provenance.
- **Entry points:** `uv run python -m collector <source> --limit N [--bundles N] [--dry-run]` and `uv run python -m collector.report`. `--bundles` caps bundles with new files; already-collected bundles don't count.
- **Pieces:**
  - `http.py`: `PoliteClient`, the only HTTP client. Checks and caches robots.txt per host, at most one request per 3 s per host, fixed User-Agent, retries 5xx twice (10 s, 30 s), never retries 403 (`BlockedError`, D-17). HTML pages are cached as raw bytes in `data/raw/_http_cache/`. `post()` sends a public search form (p-portal only) under the same rules, uncached.
  - `sources/digital.py`: Digital Agency 公募 and RFI pages.
  - `sources/pportal.py`: p-portal public search (POST with session cookie and CSRF token) for active 一般競争入札 notices, then each notice by its GET permalink. IT titles first, round-robin across 調達機関, at most 8 per org. Sets `wto_covered` and `has_english_summary` from the notice page. Fetches notice pages during discovery (cached), so a dry run costs the same requests as the real run.
  - `sources/listing.py` + `sources/sites.py`: one adapter for every local-government site surveyed in `city_survey.md`. A site is a `Site` config: listing URL(s), a regex for tender pages, its layout group's regex for attachments, license class and note. The tender page is saved as html: `notice` unless a PDF on it reads as the notice (then `tender_page`), or `result` / `qa` when its title says it only announces results or answers (`classify_page`, D-20). Pages that robots.txt disallows are skipped.
  - Adapters only find links and metadata (title, doc_type, bundle_id, license class) and set the priority order (IT first, then bundles with a spec). They never download.
  - `collect.py`: `Candidate` model, doc_type cues, `STRICT_IT_CUES` for the manifest's `is_it` (D-27), `it_and_spec_first` ordering, and `run()`: whole bundles up to `--limit` new files, URL and SHA-256 dedupe, PDF magic-byte check, PyMuPDF page count and text layer, ZIP extraction (D-21), manifest and bundle rows.
  - `manifest.py`: pydantic `ManifestRow` and `BundleRow`, validated on every read and write.
  - `report.py`: writes `data/manifests/corpus_report.md`.
- **Inputs:** live listing pages (no config files; each adapter holds its URLs and parsing).
- **Outputs:** files in `data/raw/<source>/<doc_id>.<pdf|html|zip>`, rows in `data/manifests/documents.jsonl`, bundles in `data/manifests/bundles.jsonl`, `corpus_report.md`.
- **Tests:** `tests/test_collector_*.py`, offline only: saved HTML in `tests/fixtures/collector/`, `httpx.MockTransport`, a fake clock.
- **Notes:** saves pdf, html (pages whose text is the notice, D-20) and zip. docx and xlsx are listed in dry runs and skipped. If a source needs JS rendering, use Playwright only after confirming no direct links exist.

### labeler
- **Status:** working; prompt sv4 for every labeler (Phase 3 part E, D-54); review in chat (`claude_chat`) or in a Claude Code session (`claude_code`, D-55)
- **Purpose:** the part that talks to labelers and reviewers. `eval/silver/prompt.py` builds the prompt (numbered Japanese sentences, rules, the answer envelope, the conventions block of `docs/labeling_guide.md`, and per field a compact form generated from its pydantic model in `fields.py` (`field_form`), a one-line hint and one example) and the response schema: `fields` keyed by field id with one shared entry (`$ref`), plus `normalized` keyed by field with each field's own schema, derived from the same models and made strict (every property required, no extra keys, no extractor-only values). Groq and the local model get the schema in their strict modes; Gemini gets none (JSON mode, D-49) and its answer is checked by `checks.shape_errors`. It splits long documents by top-level section. `providers.py` has three implementations of one interface: `gemini` and `groq` (plain HTTP, standard library, no SDK, no new dependency) and `local` (llama-server on 127.0.0.1, launch settings from `eval/model_feasibility.py`); each takes an optional repair turn (previous answer, problems) and reports whether the output cap cut the answer off. `review.py` writes review batches (`export`: candidates A and B without provider names, plus C: the union of A's and B's items for list fields, or a third labeler's answer on a reopened item; `export/mapping.json` says which provider each letter is), reads the reviewer's one-line answers (`import`: `accept A|B|C`, `absent`, `custom` citing any sentence of the document; records `provenance.reviewed_choice` and a line in `reviews.jsonl`), prints `review-stats`, `reopen`s an accepted consensus as a review item, and `calibrate`s two answer files for the same batch (agreement rate, differences side by side, UNSURE counts; writes nothing). `import --reviewer claude_chat|claude_code` sets `reviewed_by`; lines whose note starts with `UNSURE:` are held, not imported, in `answers/held-unsure.md` (D-55), and `accept` lines may carry a `note=`. Each batch item shows the document's license class. The instructions for a Claude Code review session are in `docs/review_session.md`; `show <doc>` prints a document's Japanese sentences for that session (read-only). `replay.py` replays a past review as a regression set (D-47).
- **Inputs:** processed documents (`eval/documents.py`), `core/shiori_core/fields.py`, `docs/labeling_guide.md`, API keys `GEMINI_API_KEY` / `GROQ_API_KEY` from the environment or `.env` (never printed, cached or logged: `keys.redact`).
- **Outputs:** model answers in `data/cache/labeling/raw/` (gitignored), review batches and `mapping.json` in `data/cache/labeling/export/`, `reviews.jsonl`, labels written through `eval/label_format.py` with `reviewed_by` `claude_chat` or `claude_code` and state `silver_model_reviewed`.
- **Tests:** `tests/test_silver.py`, `tests/test_silver_sv2.py`, `tests/test_silver_sv3.py`, `tests/test_silver_sv4.py`, `tests/test_silver_daemon.py` (fake providers; no real API, no key; the replay test is skipped when `pilot-all.txt` is absent).
- **Notes:** Yasharth's own review (heading cues, normalized values, English Summary) is still `review_note` only (D-41) and has no tool yet. The prompt, including the guide's conventions block, can be changed only by bumping `PROMPT_VERSION`. The guide's forms block must match `prompt.forms_markdown()` (test).

### silver_pipeline
- **Status:** working; prompt sv4 for every labeler (D-54), frozen until dev and test are labeled (D-58, a test holds the prompt's hash); dev run started 2026-10-11; sv3 pilot, local repair and the sv3-l1 experiment in `eval/reports/silver_pilot_sv3.md`; dev run planned in `eval/reports/dev_run_plan_sv4.md`, not started
- **Purpose:** make silver labels for the label set. `uv run python -m eval.silver [--local-focused] {keys,probe,status,plan,run,daemon,shadow,repair,resolve,report,reopen,export,import,calibrate,show,review-stats,replay}`. Who labels (D-50, `pipeline.assign`): side A is Gemini for open documents and Groq for restricted and unknown ones (never Gemini); side B is always the local Qwen3.5-9B. Side A's queue runs first, then side B's; a document is resolved once both have complete answers. Per labeler and document the requests are parts: a group of fields asked about one chunk of the document. Gemini: all fields in one request unless the estimated answer passes its output cap (never on the dev set). Local model (sv4, D-54): one grouped request with the same prompt as the cloud labelers, each group at most 60% of the output cap (8,192, or what the context leaves). With `--local-focused` (sv3-l1's call structure, D-53, version `sv4-l1`): list fields and contact one per request, then one grouped request for the rest; every request has the same system prompt and starts its user prompt with the document, so llama-server's prompt cache reuses it; the grouped request goes last because Qwen3.5 is a hybrid model and llama-server restores a cached prompt only from a checkpoint about 512 tokens before the end of an earlier prompt. Raw answers are cached under each labeler's own prompt version (`pipeline.prompt_for`); every `pre_labelers` entry records it, and `provenance.prompt_version` records `PROMPT_VERSION`. Groq: the field grouping with the fewest estimated tokens that fits its 8,000-token requests. Then: merge the parts per field (lists unioned, scalars by heading cue, conflicts kept as alternatives and flagged), run the auto checks (`checks.py`), compare the two candidates per field type with the relaxations in `agree.ACTIVE` (`agree.py`; since D-58 also `eligibility_negation`; `replay` checks every rule on all review rounds), accept what agrees and passes (`silver_consensus`), flag the rest, and send a seeded 5% of accepted fields to the review export as a spot-check. Every label the local model contributed to has `labeler_overlap` true. Documents that already have labels run in comparison mode: nothing is written but the pilot report.
- **Inputs:** `data/eval/label_set.json`, `data/eval/splits.json`, extracted sentences, provider settings and limits in `eval/silver/config.py` (`data/cache/labeling/limits.json` overrides them).
- **Outputs:** label files under `data/eval/` (open documents) or `data/eval_private/` (the rest, D-24) once all 23 fields of a document are resolved; `data/cache/labeling/{raw,resolved,decisions}/`, `flagged.jsonl`, `usage.jsonl` (one line per request of any kind, `label`, `probe` or `keys`, with outcome `ok`, `http_503`, `http_429`, `network`, ...; time, provider, model, token counts; no text), `spotcheck.jsonl`.
- **Retries:** 503 and other 5xx, per-minute 429 and network errors back off 30, 60, 120, 240 s (or the server's Retry-After) for up to 5 tries (Gemini 3, D-58: its failed requests count against 20 a day), then the part is `provider_unavailable` and that provider is paused for the rest of the run (one document's backoff is the most a run spends on an outage); the other provider goes on, and the next run retries. A daily-quota 429 stops that provider for the day; the other goes on. Gemini's and the local model's answers with shape problems (`checks.shape_errors`) get one repair request (D-49, D-52; `ProviderCfg.repair`); the local model keeps its strict schema as well, since the schema allows `normalized` null on a present field and only the shape check catches that. The local model's repair message describes each problem in plain words with the field's form and one example (`pipeline.plain_repair_message`, sv3-l1); Gemini's lists the validator's messages. llama-server's per-request timings (`cache_n`, `prompt_n`, `prompt_ms`, `predicted_n`, `predicted_ms`) are kept in the raw cache. Groq's `json_validate_failed` part is asked once more as two half field groups (D-50). An answer cut off by the output cap is recorded as `truncated` and not retried (temperature 0). There is no fallback labeler (D-50).
- **Quota guard:** `plan` prices a selection with no API calls and shows each provider's requests left today; `run` needs `--yes` and `--max-calls N` and prints what today's budgets allow, never aborting: a provider whose daily budget runs out stops for the day and the others go on; `--max-calls` stops the run (D-56). Earlier it aborted if the estimate passed either or a provider's daily budget. Failed requests count against the day's budget (Google does not say whether a 503 counts). Retries are not in the estimate, so leave room in `--max-calls`.
- **Daemon (D-62):** `daemon --gold --wave N [--yes --max-calls N] [--plan]` (`eval/silver/daemon.py`) loops over the wave's unresolved documents from `data/eval/gold_set.json`: Gemini and the local model label them (Groq never, nothing that is not open or not dev reaches a cloud provider) within each provider's remaining daily budget; a capped provider is set aside, the other goes on, and the daemon sleeps until the earliest quota reset. It resumes from `data/cache/labeling/` (no completed request is repeated), resolves with the gold export policy (every flagged field, every accepted tier 1 field, a seeded 20% of the other accepted fields), and writes `export/batch-w<N>-NN.md` when it ends. Hard stops: `--max-calls`, 3 failures in a row from one provider, laptop on battery (pause), `data/cache/labeling/STOP`; `daemon.pid` blocks a second start. `--retry-failed` asks the failed parts of the wave's documents again (also those outside `label_set.json`; D-66), the plan lists them; an authorization error (401/403) stops that provider at once and logs `auth_error`. Without `--yes` it prints the plan and makes no request. Log: `daemon.log` (events, counts, timings, doc id prefixes). Tests: `tests/test_silver_daemon.py` (fake providers, injected clock). Nothing is imported by it.
- **webimport (D-104):** `uv run python -m eval.silver webimport <dir>` (`eval/silver/webimport.py`) reads `<dir>/<8-char doc prefix>.md` (one ```json block, then an optional `## Uncertain points` list) and stores each as the raw answer of labeler `web` (model `gemini-web`, prompt `sv4-web`) in `data/cache/labeling/raw/<doc>/`, in the layout `answers`, `resolve`, `report` and `export` read; the uncertain lines are kept as `uncertain_notes`. Refuses documents that are not open license and 52bba5f9 (D-102). Checks: sv4 entry shape, every asked field present, schema 1.1.0, then `checks.run_checks`. Writes `eval/reports/web_import_check.md` (doc prefixes, field names, counts; BLOCKING failures and advisory ones apart). No network, no model, no label file. Tests: `tests/test_silver_webimport.py` (fake answer for 2f2f5bd3 in a temp directory).
- **webcheck (D-111):** `uv run python -m eval.silver webcheck --docs <ids>` (`eval/silver/webcheck.py`) is read-only: it prints each doc prefix with its license class from `data/manifests/documents.jsonl` and exits 1, naming every document that is not open (restricted, unknown, missing). Run it before any upload to a chat or provider. Tests: `tests/test_silver_webcheck.py` (temporary manifest).
- **Shadow, repair, resolve, report, reopen:** `shadow` runs a local model with the same prompt and writes only its raw cache (no label, no flag). `repair` runs the shape check on local answers cached before it existed and sends one repair request where it finds problems, no full re-run (`Pipeline.repair_cached`); the part keeps its first answer in `repair.first_response` and the repair request's own time and tokens. `resolve` resolves documents from the raw cache alone; it never makes a provider, so it cannot send a request. A document with a `web` raw answer (D-104) uses it as side A in place of the API provider's, and its label file is not written at resolve, only by `import` after the review (D-105). `report` rebuilds `eval/reports/silver_pilot_<prompt>.md` from the caches with no API call: per labeler, fields matching the existing labels of comparison-mode documents by field type with the mismatches (`compare.score`, the consensus agreement rule; Groq's sv1 answers as a reference row), Gemini's validity, repairs, requests and tokens, the local model's parts, time, truncations and JSON failures, Gemini-vs-local agreement and flags, and a projection for the dev set, all with the local answers as first sent; then a section "after local repair" and, while the local model has its own prompt version, a section for it (accuracy against every labeled document, Gemini-vs-local flags, requests, time and prompt-cache reuse, review-item projections for dev and test): the repair per document, the local model before and after against the labels, Gemini-vs-local before and after, and the single-source rule as a projection (not implemented, D-52). `reopen <doc> <field> --reason ... [--label] [--reviewed] [--with <name>[@<prompt>]]` turns an accepted consensus (with `--reviewed` also a reviewed line, as an item of kind `reopened` with a new id) back into a review item: the original labelers' answers, or with `--label` the label line itself as A, plus one more cached answer (a local model, gemini or groq, of any prompt version). Without `--reviewed` it refuses reviewed lines. A label file already written stays as it is until the review is imported, which rewrites it (the only way a written label changes). Each part's wall time (`seconds`) and output cap (`max_out`) are stored in the raw cache.
- **Notes:** dev-time only, never imported by the app. Provider policy and `labeler_overlap`: D-44, D-50. Its output is not LoRA training data until D-10 is resolved.

### debug_render

- **Purpose:** `uv run python -m shiori_core.debug_render <doc_id | path.pdf>` writes `data/processed/<doc_id>/debug/page-NNN.png` and `data/processed/<doc_id>/sentences.txt`. ### ingest
- **Status:** working (Phase 2 part C)
- **Purpose:** open a PDF, extract every page's lines, classify each page, read scanned and outlined pages with OCR, mark table cells (text and mixed pages), flag furniture, segment into sentences. `load_document(path, ocr=True) -> Document` runs pipeline steps 1 to 5 (`ocr`: True = the default engine, loaded on the first page that needs it; an engine instance; False = leave such pages empty); `classify(char_count, suspect, image_cover, drawing_count) -> PageKind`.
- **Page kinds (tuned on the 1,864 corpus pages, see extraction_report.md):** 20+ usable characters -> `text`, or `mixed` when images cover 50%+ of the page. Fewer -> `scanned` if images cover 40%+ (copier scans 95-100%, Asahikawa's scanned pages 51%), `outlined` if 2,000+ path segments (Print To PDF pages have 9,700 to 46,000; other thin pages under 5), `blank` if no characters at all, else `text` (a short page). Corpus result: 1,818 text, 10 mixed, 12 scanned, 21 outlined, 3 blank.
- **Suspect characters:** U+FFFD, control characters, Phonetic Extensions and CJK Extension A. In this corpus they only come from vertical-form glyphs mapped to the wrong code point (TXT-14). Usable characters = all minus suspect. A garbled page that still has some characters stays `text`; the report lists pages with 5%+ suspect characters.
- **OCR (D-36):** `scanned` and `outlined` pages are rendered at 200 dpi and read; their lines (source `ocr`) replace the empty text layer and go through clean, normalize and segment unchanged; no table cells on those pages. `mixed` pages keep their text layer (the text inside their images is not read, open question). Raises `OcrUnavailableError` if the engine's files are missing.
- **Locked PDFs:** `PasswordProtectedError`; callers skip the file.
- **Watch for:** pages with no text layer *and* no images, where the text is drawn as vector outlines (doc `7c76af66d35dec3e4a82f4a7ef985809119e2d6230641c9a57dd99fc68e4a5e6`, Toyama City, producer "Microsoft: Print To PDF", about 36,000 path segments on page 1). An image count can't detect these, so they need the same OCR path as scans: render the page, then OCR. A second one (Asahikawa) comes from the same "Microsoft: Print To PDF" producer, so that producer string is a useful hint. Also decide per page, not per document: some text PDFs contain a single scanned page (Asahikawa, D-23).

### extract_text
- **Status:** working (Phase 2 part A)
- **Purpose:** characters with bounding boxes from the text layer, grouped into lines in reading order. `page_lines(pdf, index) -> list[Line]`.
- **How:** MuPDF cuts text into fragments wherever the pen jumps (justified text and label-value rows are several fragments per line). Fragments in one block are joined along their writing direction when on the same baseline with a gap of at most 1.5 line heights; across blocks only when touching (gap 0.1, for a 外字 image that starts a new block). Single upright non-ASCII characters are chained into a column when stacked with a gap of at most 0.2 character widths, across blocks. Lines from 縦書き fonts (wmode 1), stacked columns and rotated text are flagged `vertical`. Reading order: MuPDF blocks sorted top-to-bottom (4 pt buckets), then left-to-right, in displayed coordinates; lines inside a block keep the PDF's order.
- **Invariant:** no character is added, changed or removed: `line.text == "".join(c.c for c in line.chars)`. Lines of only space glyphs are kept.
- **Known limits:** no column detection (two-column pages would interleave); letter-spaced vertical text stays one character per line (open question); vertical lines are flagged but their reading order (right to left) is not solved; fonts with no ToUnicode map would show up as suspect characters, none in this corpus.

### ocr
- **Status:** working (Phase 2 part C, D-36)

### normalize
- **Status:** working (Phase 2 part B)
- **Purpose:** produce `text_norm` plus `norm_to_orig` offset map. `normalize(text, marker_end=0, joins=()) -> (text_norm, norm_to_orig)`; `joins` are the places where lines were joined into the sentence.
- **How:** one character at a time: circled numbers and circled katakana (TXT-3) and PUA characters (TXT-11, TXT-12) are kept; everything else goes through NFKC (one original character may give several, all pointing back to it; a combining mark is composed onto the previous character); then lookalikes (TXT-4, TXT-14's six read-off code points, TXT-16, `ー` between digits). Where lines were joined and both sides are Latin letters or digits, one space is put back and mapped to the line break (TXT-17; `Japan` + `TEL`); it is never removed again. Last, single spaces are removed between digits, between a digit and `年月日時分円万億` either way, between an era name and a digit (TXT-9), and inside letter-spaced CJK runs (TXT-10), except the spaces right after the list marker (`text[:marker_end]`, found by segment), so `５ １次選考` stays `5 1次選考`.
- **Guarantee:** every `norm_to_orig` entry is a valid index into the text and the map never goes backwards (property test over random text and every fixture sentence).
- **Not here:** 外字 placeholders (TXT-12 suggests one; PUA is kept as is for now); kanji variants beyond `髙 﨑 邊`.

## Store (`app/electron/store.ts`, shipped)

- **Status:** started (Phase 8, D-119, `storage_design.md` section 6 steps 1 to 3). Seal and open, save, list, read, add translations, delete, delete all and startup cleanup work in tests with a fake keeper. The real keeper (`app/electron/keeper.ts`, step 3) is tested with a fake `safeStorage`; with the real one it was checked by hand once, on macOS in a dev run, through a throwaway script (2026-11-27). No app code imports any of these three files, so the app saves nothing. `main.ts` takes the single instance lock.
- **Purpose:** the main process keeps saved documents as encrypted files, one folder per document, with a key per document wrapped by a master key (Electron `safeStorage`, in `keeper.ts`). Saving is off until the user says yes. Delete = destroy the wrapped key, then the folder.
- **Interface:** `seal(key, folder, role, plain)` and `open(key, folder, role, blob)`, both returning a Buffer. `role` is `key`, `record` or `source`. Blob: `SHI1`, 12-byte nonce, ciphertext, 16-byte tag (AES-256-GCM, Node `crypto`). `createStore(base, keeper, log = console.error)` works under `<base>/store` and returns `save(result, sourcePath, appVersion)`, `list()` -> `{documents, unreadable}`, `read(docId)`, `readSource(docId)` (the PDF bytes; null for HTML, whose text is in the result) `addTranslations(docId, modelId, items)` -> boolean, `deleteDocument(docId)` -> boolean (false if no readable document has the id; removes the `key` file first; throws `locked` without the master key), `deleteAll()` (every folder, then `store/` with the master key; decrypts nothing, so it works when locked) and `cleanup()` (startup: removes `.tmp` files and folders without `key`; removes nothing when locked). Delete does not reach old disk blocks or earlier backups. `Keeper` is `wrap(text) -> Buffer` and `unwrap(Buffer) -> text`, used for the master key only. A `StoredDocument` is `{id, format, added, results: {model: {app_version, result}}, translations: {model: {sentence id: translation}}}`, with model `none` for rules only. Saving a model's result again keeps only the translations whose Japanese did not change. Any failure throws `StoreError` with a code (`seal_failed`, `open_failed`, `locked`, `source_changed`, `save_failed`, `read_failed`, `delete_failed`) and nothing else; log lines are `store_saved bytes=N`, `store_deleted`, `store_deleted_all folders=N`, `store_cleanup folders=N` and `<event> failed: <type>`. `createKeeper(safeStorage, platform)` (`keeper.ts`) returns a `Keeper`, or `no_keyring` when encryption is unavailable or, on Linux, the backend is `basic_text` or `unknown`. `settings.ts`: `readSaveDocuments(base)` gives `unanswered`, `yes` or `no` and never throws; `writeSaveDocuments(base, "yes" | "no")` writes `<base>/settings.json` atomically, makes the folder if needed, and returns `saved`, `not_available` (`base` is `no_local_folder`; nothing is created) or `failed`.
