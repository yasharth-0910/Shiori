# Source survey (Phase 1, part A)

Date: 2026-10-02. Covers every source in `docs/sources.md` section 1, plus Funabashi City, added as a local-government source that can actually be crawled.

How it was done: plain HTTP GET/POST with an honest User-Agent (`ShioriResearchBot/0.1`) that carries a contact address, at most one request every 3 seconds per host, every response cached locally. No logins, no forms with personal data, no JavaScript execution, no retries with a different User-Agent. About 70 requests in total. The probe scripts were throwaway and are not in the repo; the findings below are what they produced.

Sample PDFs are in `data/raw/_samples/<source>/` (gitignored) with rows in `data/manifests/documents.jsonl`. `text_layer` uses a quick check: a page counts as having text if PyMuPDF extracts 20 or more non-space characters from it.

## Best sources for IT and system procurement

1. **デジタル庁.** Nearly every item is IT (ガバメントクラウド, GSS, 公共サービスメッシュ, 設計・開発, 運用). Direct PDFs, a clear license (PDL1.0), long specs (the RFI 調達仕様書 sample is 37 pages). The catch: the 一般競争 bid bundles themselves are on GEPS.
2. **Local-government proposal pages (Funabashi as the first example).** Full bundles with 仕様書 for system procurement, as static HTML with direct links. The catch is licensing: they can be used locally but not published.
3. **調達ポータル.** The largest pool of IT notices (236 active with システム in the title), with English Summaries on WTO notices, which helps label checking. But it gives notice text only, as HTML, unless someone downloads the bundle from GEPS by hand.
4. **JMA MSC and similar agency pages.** Some IT titles (配信サービス構築, 情報提供装置), but very few documents. Useful for org variety, not volume.

## Proposal: first two collector adapters

Not built yet. For review.

**1. `digital` (Digital Agency).** Mostly IT, which is the use case that matters most. Static HTML with direct links, no JavaScript, and a license that allows republishing with attribution (PDL1.0), so these files can go into a public eval set in Phase 9. Scope: the 公募, RFI (open and closed) and 意見招請回答 listings, plus each 公募 detail page. Group files on the same page into one bundle (`bundles.jsonl`).

**2. `funabashi` (local government, static proposal pages).** Supplies the full bundles (要領 + 評価基準 + 仕様書) that national sources keep behind GEPS, and a different issuer template. The layout (`index.html` -> `p<id>.html` -> `p<id>_d/fil/*.pdf`) is a common Japanese municipal CMS pattern, so the same adapter may work for other cities on the JETRO `links-local.html` list with only a config change. Files are marked "do not republish" in `license_note` until the open licensing question is answered. If that is unacceptable, swap in a local government whose site uses PDL1.0 or 政府標準利用規約. Checking which cities do is cheap and is the next survey step.

Why not p-portal first: it can be crawled, but without GEPS it only gives HTML notice text. A small p-portal adapter that stores notice HTML (with the English Summary) is still worth adding third. It would give org variety and a link from 調達案件番号 to JETRO.

### Shared collector pieces (sketch)

All in `collector/`, dev-time only, built on httpx and beautifulsoup4.

- **`http.py`: one polite client.** A wrapper around `httpx.Client` with a fixed User-Agent (from config), a per-host minimum interval of 3 s (a dict of host -> last request time; sleep before each request), and a robots.txt check through stdlib `urllib.robotparser`, fetched once per host and cached. A disallowed URL raises instead of fetching. Raw HTML responses are cached on disk under `data/raw/_http_cache/` keyed by URL hash, so re-running an adapter costs no requests.
- **Adapter interface.** A plain module per source with one function, `discover(client) -> Iterator[Candidate]`, where `Candidate` is a pydantic model holding url, landing_url, issuer_org, title_ja, doc_type, notice_date, bundle_key and license_note. Adapters only find links and metadata. They never download. No base class until there are two adapters that clearly share more than this.
- **Fetch and cache by SHA-256.** One shared `fetch(candidate)`: skip if the URL is already in the manifest. Otherwise download, check for the `%PDF` magic bytes (docx/xlsx get their own check or are skipped for now), hash the bytes, skip if that SHA-256 is already in the manifest (the same file posted under two URLs), write `data/raw/<source>/<sha256>.pdf`, then run the text-layer check.
- **Manifest writer.** Validates each row with a pydantic `ManifestRow` that matches `data/README.md`, and appends one JSON line to `documents.jsonl`. It loads existing doc_ids and URLs once at startup for the dedupe checks. Append-only; corrections are made by hand with a note.
- **CLI.** `uv run python -m collector <source> [--limit N] [--dry-run]`. `--dry-run` prints candidates without downloading, which is how a new adapter gets checked against the live site.
